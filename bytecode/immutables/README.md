# Immutable parity fixtures

The nine fixtures in `parity-fixtures.txt` cover declaration-order offsets,
constructor arguments, sender addresses, constructor reads, and a runtime-only
internal function in a program with a constructor. The widening fixture stores
a `String[10]` constructor argument into an immutable `Bytes[100]`; its copy
uses the runtime length so it does not read the larger target capacity from
the smaller source buffer. `oracle/` contains annotated
AST/layout inputs and deploy/runtime bytecode generated by pinned Vyper
0.5.0b1 with the patches in `../patches/` (including vyperlang/vyper#5332 and
#5338). Its provenance records source/output hashes and compiler
settings: optimization NONE, experimental code generation, Prague, and no
bytecode metadata.

With the pinned Vyper environment on PATH and its Python interpreter selected:

```sh
python bytecode/memory_store_witnesses.py prepare \
  --corpus immutables --fixtures /tmp/immutable-oracle --check
```

The native runner checks exact deploy/runtime bytecode parity for the
witnessed fixtures (`../native/README.md`); from `bytecode/`:

```sh
./native/bytecode_parity_native.exe . immutables
```

`compilerLoweringTest` (`tests/compilerLoweringTestScript.sml`) checks source
deployment and `get() = 42` for p23.

## Installed bytes and padding

Installed code uses an actual section witness, related to source immutable
values by [immutables_section_rel](../../lowering/proofs/immutableSectionRelScript.sml).
Unused string/byte capacity and inactive dynamic-array elements may vary;
source values alone do not determine those bytes. The canonical encoder remains
a possible witness, rather than a deployment invariant.

The [padding regression](../immutable_padding_probe.py) compiles and executes
clean, dirty, and conditional constructors in a Prague EVM. The dirty source buffer used to leak its following word into unused
immutable capacity. Runtime-length copying leaves that capacity untouched;
all four executions now install the same bytes and return the same string.
This regression does not impose a general canonical-padding invariant. The script also deploys the widening-conversion fixture with empty, one-byte
and ten-byte inputs and checks its getter. It checks that
p23 installs its runtime followed by the 32-byte encoding of 42 and returns 42
from `get()`.

```sh
uv run --with py-evm==0.12.1b1 python \
  bytecode/immutable_padding_probe.py \
  --vyper-python /path/to/pinned-vyper/bin/python
```

The EVM regression executes constructor bytecode directly, without a CREATE
transaction. The constructor-copy and staging proofs transport actual bytes
without assuming canonical padding. The
[code-layout bridge](../../lowering/proofs/immutableCodeLayoutScript.sml) uses the
computed final `code_end` header and the assembler's existing `asm_encoding_wf`
condition.

# Deep-DUP differential fixtures (issue 562)

These are the two nested-array witnesses from issue 562. `cases.json` contains
all ten inputs and independently ABI-derived calldata/result words. `oracle/`
contains pinned-Python annotated AST/layout, deployment/runtime bytecode and
provenance. No expected bytecode is generated by HOL.

The deep-DUP implementation and proof repairs are complete. The parity manifest
keeps fixture activation pending #551; the whitelist is unchanged.

`check_runtime.py` checks the ABI vectors, requires successful checker/compiler
probe stages ending in `MATCH`, compares deployment/runtime bytes, and executes
all ten inputs on both runtimes. Missing acceptance, incomplete probes, reverts
and incorrect return data fail validation. It continues through runtime cases
when byte parity or an earlier case fails.

## Reproduction

Use the pinned environment from the [parent README](../README.md): VYPER_PIN,
Python 3.11.11, uv 0.10.11 and the oracle dependency constraints. Runtime execution
also needs py-evm 0.12.1b1 with `PragueVM`. From the repository root:

```sh
python3 lowering/defs/bytecode/deep-dup/check_runtime.py --self-test
python3 lowering/defs/bytecode/memory_store_witnesses.py prepare \
  --corpus deep-dup --repo "$PWD" --fixtures /tmp/deep-dup-python
diff -r lowering/defs/bytecode/deep-dup/oracle /tmp/deep-dup-python
python3 lowering/defs/bytecode/memory_store_witnesses.py probe \
  --corpus deep-dup --repo "$PWD" --fixtures /tmp/deep-dup-python \
  --output /tmp/deep-dup-hol
python3 lowering/defs/bytecode/deep-dup/check_runtime.py \
  --python-dir /tmp/deep-dup-python --hol-dir /tmp/deep-dup-hol
lowering/defs/bytecode/python-o1-bytecode-fixtures --compare-hol \
  --vyper-repo /path/to/clean/pinned/vyper
```

Oracle generation uses experimental codegen, Prague, optimization NONE and no
bytecode metadata. The probe records checker acceptance and exact compiler output;
the runtime checker validates those stages as well as the bytecode and behavior.
Deployment bytes are compared but are not executed by this runtime runner.

Complete witness success requires #551's separate lowering repairs. Activate the
prepared fixtures after #551 is integrated, preserving the frozen base corpus.
